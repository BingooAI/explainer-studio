# ENGINEERING.md — Project constitution (read this BEFORE doing anything)

> This file governs every change to this repository. If a request or an idea contradicts it,
> **stop and ask** — do not quietly break the rules.
>
> **Explainer Studio** — an open-source studio by [Bingoo.ai](https://bingoo.ai) that turns a
> lesson brief into an editable explainer video: script, visuals, narration and timeline,
> generated by a model, then edited scene by scene and exported. Self-hostable,
> model-agnostic, runs fully on localhost. **Apache-2.0 throughout.**
>
> **Language of record: English.** Source, comments, docs, commits, issues, PRs.
> Vietnamese lives in `README.vi.md` and the docs-site translation — nowhere else.
>
> The design is specified in **[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)**. Read it
> before writing code. Changing it requires an ADR in `docs/adr/`.
> **[`docs/PRODUCT.md`](docs/PRODUCT.md)** says who this is for, what it produces, and in
> what order it ships — read it when a decision turns on who is affected.

## 0. WORKFLOW — read and follow this first

**Do not start coding. For any non-trivial change, always:**

1. **Brainstorm + plan → WAIT FOR APPROVAL.** Present: the problem, **at least 1–2 options**
   with trade-offs, and a step plan. Start only when approved. Never code first and report
   after. (Obvious bug fixes / typos / direct instructions can go ahead — still report the
   impact.)

2. **Reuse before creating.** Before writing any module / util / type / package: **search
   hard for what already exists** — grep the barrels in `packages/*`. Prefer extending over
   adding. Never duplicate logic.

3. **Assess impact before touching anything shared.** Changing a schema, a port, a registry
   contract, a profile or a public export: **grep every call site**, state the blast radius,
   and say plainly whether it is a breaking change. Put it in the plan.

4. **Always weigh 5 axes** and write them into the plan:
   **impact · consequences · extensibility · reusability · security.**

5. **Self-test end-to-end.** Run the affected path for real — happy path **and** edge cases —
   plus `pnpm lint && pnpm typecheck && pnpm test && pnpm build`. Do not rely on typecheck
   alone. Report results honestly, pass or fail, with evidence.

> Spirit: **plan first — get approval — reuse hard — foresee impact — test properly.**
> Quality and safety over speed.

## 1. GOLDEN RULES (invariant — never violate)

| #       | Rule |
| ------- | ---- |
| **R1**  | **Dynamic by default — nothing hardcoded.** Anything a user, deployer or contributor might reasonably change is a **registry entry, a profile or config** — never a literal, never a `switch` on a vendor name. If extending the product means editing a `case` branch, the design is wrong. See ARCHITECTURE §2. |
| **R2**  | **The checker is code, never a model.** Validators, gates and invariants are pure and deterministic. **A gate MUST NOT call an LLM.** Trust comes from the checker, not the model — a weaker model yields a worse lesson, never an invalid one. |
| **R3**  | **`frame(program, t)` is pure.** Same `t` ⇒ same `RenderModel` ⇒ identical pixels on every renderer. Renderers paint; they never own timing, layout or easing. Break this and the renderers silently drift apart. |
| **R4**  | **Structure ⟂ language.** `ExplainerDoc` is language-neutral; every human-readable string lives in a `LocaleBundle`. **No natural-language text, speech-rate constant or glyph metric may be hardcoded in the engine** — those are locale packs. |
| **R5**  | **Authors declare intent, never milliseconds.** Scenes say `reveal` / `emphasize` / `drawOn`. Timing and easing live in a versioned profile. Documents pin profile versions so today's lesson renders the same after we retune. |
| **R6**  | **Elements have no coordinates.** They name a layout `region`; `resolveLayout` computes rects. Coordinates stay *unrepresentable* in the authoring schema — that is why generated layouts cannot overlap. |
| **R7**  | **Packages are platform-pure.** `kernel`, `core`, `quality`, `providers`, `generator` must not import `react`, `next/*`, `react-native`, or Node builtins (`node:*`, `fs`, `path`, `crypto`), and must not call `fetch`, `process.env`, `Date.now()` or `Math.random()`. Platform concerns are injected through ports. Enforced in CI. |
| **R8**  | **Never require one vendor.** Anthropic, OpenAI-compatible and Ollama must all work. **No hardcoded endpoint — nothing may assume `bingoo.ai` exists.** Requiring our key would make this a sales funnel in disguise, and the community will say so out loud. |
| **R9**  | **The localhost guarantee.** `git clone && pnpm install && pnpm dev` gives a working studio with **no account, no API key, no network call**. This is tested in CI, not a best effort. Never merge anything that breaks it. |
| **R10** | **Model output is untrusted input.** Zod at every boundary; whitelist against the registry, clamp numbers, drop invented ids, never render model output as markup. Content moderation is a **configurable stage, off by default** — so never describe default output as moderated or classroom-safe, and never let a feature quietly depend on it having run. |
| **R11** | **Provenance on everything generated.** Record `{model, promptVersion, contractVersion, profileVersions}`. Runs must be auditable and re-runnable. |
| **R12** | **No secrets, no student data.** This repo processes **curriculum, not learners**. Never add a student PII model. BYO API key; never log a key, or a prompt containing one. Never commit `.env`. |
| **R13** | **No hotfix culture.** Fix bugs at the layer that owns them, with a regression test, behind the same gates as any other change. No special case for one lesson, one tenant, one model. If it must differ per deployment, design a config surface. |
| **R14** | **Parity: openness must not be marketing.** Anything a hosted instance can do, a self-hosted install must do with its own keys. Hosting may add convenience — never capability. Equally, **the Settings UI and the config file write the same resolved shape** — never ship a setting reachable only by editing YAML, because a teacher will never edit YAML. See ARCHITECTURE §12. |
| **R15** | **Write errors for the person reading them.** In their language, saying what to do next. A teacher must never see a raw status code, a stack trace, a model ID they did not choose, or a disabled button with no explanation. A failed key falls back down the routing chain and says so; it never blocks the work. |
| **R16** | **The packages must stay embeddable.** No module-level singletons — the registry is an instance you construct, so two lessons or two tenants never share state. `"sideEffects": false`; `react` as a peer dependency; no ambient `process.env`, global fetch interception or assumed origin. A document stores media *references*, never a bucket-specific URL. See ARCHITECTURE §13. |
| **R17** | **Agents loop only where a deterministic verifier closes the loop** — and an agent is never the verifier (R2). Every loop is hard-bounded: max iterations, token budget, wall-clock, cost ceiling. No agent has side effects; agents propose, the pipeline persists after gates. Extended thinking is a declared provider capability, never a requirement — no stage may work only on a frontier model. No agent-framework dependency. See ARCHITECTURE §8. |
| **R18** | **The teacher approves the brief before generation runs.** Objectives and facts are proposed, never assumed. Uploaded material is untrusted input — prompt injection through a PDF is a real path. The teacher owns *what* is taught; the studio owns *how* it is staged. |
| **R19** | **Done means green.** `pnpm check` passes — build, then lint, typecheck and test. Build comes first because packages resolve each other through `dist/`; checking before building silently degrades every cross-package type to `any`. See §10. |

## 2. "Where does this go?" — the code map

Decide the layer before writing anything. Full detail in
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) §3–§13.

| Kind of work | Goes in | Notes |
| --- | --- | --- |
| Registry primitives, config resolver, shared error type | `packages/kernel` | Pure; zod its only dependency. Depended on by everything, depends on nothing here (ADR 0002). |
| Document schema, layout, choreography, `frame`, type scale, profiles | `packages/core` | Pure, zod-first. The engine. |
| Lint, layout gate, pedagogy/arc gate, generated authoring contract | `packages/quality` | Pure + deterministic. **No LLM** (R2). |
| Port interfaces, provider registry, cue sync, image resolution | `packages/providers` | Pure. No vendor names, no I/O. |
| Outline → write → moderate (opt-in) → critic → regen | `packages/generator` | Pure; the LLM arrives as a port. |
| SVG renderer, player, element painters | `packages/react` | Paints `RenderModel` only (R3). |
| Scene editor: `EditOp` layer, timeline, panels | `packages/editor` | Every mutation is a pure op with an inverse. |
| First-party primitives, manipulative kits, content packs | `packages/kits` | Pure except the painter. Manifest + `examples.json` + SPDX licence mandatory; **no bundled assets — a kit draws itself and must render with no provider configured** (ARCHITECTURE §10). |
| Concrete LLM / TTS / image / moderation / storage implementations | `packages/adapters` | **The only place a vendor is named.** |
| The self-hostable Next.js product | `apps/studio` | |
| HTTP API, persistence, media, provider wiring | `apps/server` | Server-only. |
| `init · generate · validate · render · export` | `apps/cli` | Lessons as code: git-versioned, CI-gated. |
| Document format spec | `docs/spec` | The thing we most want copied. |
| Architecture decisions | `docs/adr` | |

If a package does not exist yet, it is not that phase yet — **do not invent packages.**
Phasing is in ARCHITECTURE §16.

## 3. Registries — how to extend anything

Adding a provider, template, theme, locale, question kind, interactive kit or exporter
**must not touch an existing file.** You add a descriptor and a factory, and register it.

- A registry entry is **data + a factory**, validated by zod on registration. An invalid
  descriptor fails loudly at startup, never silently at render.
- `template`, `gate.kind`, `element.type` and `emphasis` are **registry keys, not frozen
  enums**. The schema validates that the key resolves; the registry decides what exists.
- **Capabilities are declared, not assumed.** Ask the descriptor *"does this support word
  timings?"* — never *"is this OpenAI?"*
- **Model IDs are never literals in code.** They come from config; where a provider can
  enumerate its own models, the UI lists them live.
- Routing and failover are an ordered config list, not an `if` chain.
- The authoring contract is generated from the live registries, so a newly registered
  template documents itself to the model automatically.

**Acceptance test for any extension work:** could a third party add this from outside the
repo, with no fork? If not, it is not done.

## 4. Configuration

Precedence, lowest to highest: **built-in defaults → config file → environment →
workspace/project settings → runtime UI settings.** One resolver, one validated shape, one
place to read it.

- Changing a setting must not require a rebuild, and where safe, not a restart.
- Secrets resolve through env interpolation and stay server-side. Config is safe to commit;
  `.env` never is.
- Never read `process.env` outside the config resolver. Pure packages never read it at all.

## 5. Coding conventions

- **TypeScript strict.** No casual `any`, no bare `@ts-ignore` / `eslint-disable` (if truly
  needed, comment the reason).
- **ESLint type-aware** is on (`no-floating-promises`, `no-misused-promises`,
  `await-thenable`…). Handle promises properly; **do not disable the rule**.
- **Zod is the source of truth.** Every type is `z.infer<>` — the validator and the type
  cannot drift. Parse at every boundary.
- **Write like the code around you** — same comment density, naming, idioms. No filler
  comments. Comment the *why* and the constraint, never the *what*.
- `import type` for types. Barrel exports stay curated — the public API is a contract.
- **Determinism:** no `Date.now()` / `Math.random()` in pure packages — inject via ports.
  Golden tests must stay reproducible.
- **Every package builds** via `tsup` → ESM + CJS + `.d.ts` with a real `exports` map. Never
  export raw `.ts` — a package that only compiles inside this repo is not usable by anyone.
- **Accessibility is not optional:** WCAG 2.2 AA, `focus-visible`, `aria-*`, correct `alt`,
  honour `prefers-reduced-motion`. In education this is frequently a legal requirement.
- Never edit generated files (`dist/`, `generated/`, `contract/`).
- Format with Prettier (`pnpm format`).

## 6. Open-source project standards

**Project furniture** — `LICENSE` (Apache-2.0) + `NOTICE` · `README.md` (EN) +
`README.vi.md` · `CONTRIBUTING.md` · `CODE_OF_CONDUCT.md` (Contributor Covenant 2.1) ·
`SECURITY.md` · `GOVERNANCE.md` · `MAINTAINERS.md` · `CHANGELOG.md` (Keep a Changelog) ·
`SUPPORT.md` · `.github/` (issue + PR templates, `CODEOWNERS`, `dependabot.yml`, workflows) ·
ADRs in `docs/adr/` · an RFC process for anything that changes the document format or an
invariant.

**Licensing.** Apache-2.0 for the whole repository — patent grant, enterprise-safe, easy to
contribute to. Every source file carries an SPDX header; the repo is REUSE-compliant:

```ts
// SPDX-FileCopyrightText: 2026 Bingoo.ai
// SPDX-License-Identifier: Apache-2.0
```

**The copyright holder is `Bingoo.ai`** — one name, used consistently everywhere. Note that
copyright and licence are different things: ownership stays with Bingoo.ai, and Apache-2.0
is what we grant on top of it. **Never strip a copyright line to make something "more
open"** — it removes our ability to prove ownership, which is the very thing that gives us
the right to license it, and unowned code is what enterprises refuse to adopt.

Relicensing is **irreversible** once published. Before bringing in code from elsewhere —
including our own private repos — confirm authorship (no unassigned contractor work) and
screen for third-party code with an incompatible licence.
BSL/SSPL are not options — they are not OSI open source. The licence covers the code; the
**trademark policy** covers the name. Apache-2.0 grants no right to the "Bingoo" name.

**Contributions: DCO sign-off (`git commit -s`). No CLA — deliberately.** Without a CLA we
structurally cannot relicense, so we cannot rug-pull even if we wanted to. That is a
constraint, not a promise, and it is the strongest trust signal we have.

**Supply chain & release**

- OpenSSF Scorecard + Best Practices badge; SPDX headers, REUSE-compliant.
- CycloneDX SBOM per release; Sigstore signing; npm provenance.
- GitHub Actions pinned by commit SHA. 2FA enforced on the org and on npm.
- Conventional Commits + changesets. SemVer, with the document format versioned separately
  from the packages.

**Education standards** — the document format should interoperate, not island:
**SCORM 1.2/2004 · xAPI** (feed the LMS people already run), **QTI 3.0** for question kinds,
**WebVTT/SRT** captions, **WCAG 2.2 AA**.

**Commit authorship.** Every commit is authored by the contributor who made the change, and
by nobody else. No attribution trailers or footers of any kind are added to a commit message
or a PR body. The history is the work of the people whose names are on it.

**Claim discipline — do not overclaim, ever.** We say: *"every lesson is validated by
deterministic gates before it can be saved."* We do **not** say "hallucination-free," and we
do **not** say "safe for classrooms" or "moderated." Gates catch *structural* errors, not
*factual* ones — a false statement inside a structurally perfect lesson will pass — and
content moderation is off unless a deployment configures it. Say what the gates actually
check, and put the review responsibility where it truly sits: with the teacher. One viral
counterexample would cost more than the claim ever earned.

## 7. Branching, commits and versioning

### Branches

**Trunk-based. `main` is always releasable** — protected, no direct pushes, no long-lived
`develop`. A parallel integration branch is overhead a project this size cannot repay, and
it is where outside contributors get lost.

```
type/short-kebab-description        feat/kit-registry · fix/cue-drift · docs/product-plan
```

Types match the commit types below: `feat · fix · docs · refactor · test · perf · chore · ci`.

- **Short-lived.** Branch, PR, merge, delete. A branch open longer than a few days is a
  planning problem, not a git problem.
- **Squash merge** into `main` — one logical change, one commit, readable history.
- Outside contributors work from forks; maintainers may branch in-repo.
- `release/N.x` branches exist **only** to patch an old major after the next one ships.
  Never as a staging area.

### Commits

**Conventional Commits**, with a scope when it helps: `feat(core): add pose interpolation`.
`feat!:` or a `BREAKING CHANGE:` footer marks a break.

- **DCO sign-off on every commit** (`git commit -s`). No CLA — see §6.
- **No attribution trailers or footers** in a commit message or a PR body. See §6.
- The commit body explains *why*. The diff already shows *what*.

### Four version lines — know which one you are changing

This project versions four things independently. Confusing them is how a lesson silently
renders differently a year later.

| What | Scheme | Who pins it | Breaking means |
|---|---|---|---|
| **Packages** | SemVer, **lockstep** — all packages share one version | consumers, via npm | A published export changed shape or behaviour |
| **Document format** | `explainer/vN` — major only | every document, in its `version` field | An old reader can no longer read a new document |
| **Profiles** (timing, layout, type scale, speech metrics) | SemVer | each document, in `profiles` | The same document would render differently |
| **Kits** | SemVer per kit | each document that uses the kit | Behaviour, params or grading changed |

**Packages are versioned in lockstep** — one version across the repo. Independent versioning
is more precise and produces a compatibility matrix nobody maintains; these packages are
designed to be used together, so the precision buys nothing and costs clarity.

### Document format rules — the strictest ones here

A lesson must outlive the tool (ARCHITECTURE §13.1), so:

- **Additive changes stay within the current major**, and only if an older reader can safely
  ignore the addition.
- **A breaking change means `explainer/v2`, and the converter ships with it** — never after.
  No format bump without a working `v1 → v2` migration and golden tests proving a corpus of
  real lessons survives it.
- **Never silently reinterpret an existing field.** That is a breaking change wearing a
  disguise, and it is the kind that corrupts documents rather than failing loudly.
- Profiles exist precisely so house-style tuning is **not** a format change (§2.3). Use them.

### Releases

- **changesets** on every PR that changes a public API. No changeset, no release note — CI
  fails the PR rather than letting it slip through.
- Release PR → merge → CI publishes with **npm provenance**; tags are `vX.Y.Z`.
- Channels: `latest` for stable, `next` for prereleases (`1.0.0-rc.1`).
- **Deprecate for one minor, remove in the next major.** Deprecation warns at runtime and in
  the docs; silent removal is never acceptable.
- Per-export stability tiers — `stable` / `beta` / `experimental` — declared and honoured.
  An `experimental` export may break in a minor; a `stable` one may not.

### 0.x and the road to 1.0

We start at **0.1.0**, published after Phase 2 (PRODUCT §5), and stay pre-1.0 while the
document format is still moving. In 0.x a minor may break — say so plainly in the changelog
rather than pretending otherwise.

**1.0 means one thing: the document format is stable and we commit to migration paths for
it.** Not "feature complete", not "polished" — a specific, checkable promise about
compatibility. Do not ship 1.0 for marketing reasons; the number is a contract with everyone
who authored a lesson.

## 8. Testing

Tests are not a phase at the end. **Untested code is not done** (R19), and in a project
whose entire pitch is "deterministic gates you can trust", a weak test suite undermines the
product claim, not just the code.

### What each layer gets

| Layer | Test kind | The bar |
|---|---|---|
| `core` (schema, layout, choreographer, `frame`) | **Unit + golden fixtures** | Every public function. Golden files for `frame()` output. |
| `quality` (the three gates) | **Unit, exhaustive on failure modes** | Every lint rule and finding type has a failing fixture *and* a passing one. |
| `providers`, `generator` | **Unit with stub ports** | A deterministic fake `LlmProvider`. Never a real network call. |
| `adapters` | **Contract tests** | One shared suite every adapter of a port must pass. |
| `kits` | **Golden, from `examples.json`** | The mandatory examples *are* the corpus. |
| `react` | **Component + a11y** | Renders `RenderModel` correctly; axe reports no violations. |
| `apps/*` | **E2E (Playwright)** | The critical paths of PRODUCT §3, including the keyless path. |

### Rules that matter more than coverage percentage

- **Determinism is a test, not a hope.** `frame(program, t)` called twice must produce
  deeply-equal output, and the golden corpus must not shift. This directly guards R3, which
  nothing else can check.
- **No network in unit tests, ever.** A test that reaches a provider is an integration test
  and lives behind a flag. This also keeps the suite honest about R9.
- **Property-based tests for the schema layer.** Round-trip `parse → serialise → parse` and
  fuzz malformed documents. A format that outlives the tool (PRODUCT §2) has to survive
  input nobody anticipated.
- **Every bug fix ships with the regression test that would have caught it.** This is what
  R13 means in practice — no fix without a test is a hotfix wearing a disguise.
- **Coverage is a signal, not a target.** Meaningful thresholds on pure packages; do not
  chase a number by testing getters. A gate with 100% coverage and no failure-mode fixture
  is worse than an honest 70%.

### Accessibility is tested, not reviewed

axe runs in CI on the player and studio. Keyboard traversal, focus order and
`prefers-reduced-motion` are asserted, not eyeballed. WCAG 2.2 AA is frequently a legal
requirement in education (ARCHITECTURE §15) — a manual check that happens sometimes is not
compliance.

## 9. Security

### Threat model — know what is actually untrusted

Four untrusted inputs, and they are the ones to design against:

1. **Model output** (R10) — parse with zod, whitelist against the registry, clamp numbers,
   drop invented ids, escape on render. **Never render model output as markup.** Content
   moderation is opt-in, so assume it did not run.
2. **Teacher-uploaded material** — a PDF or slide deck reaching the model is a real prompt
   injection path (R18). Confine the model's output to the document schema; instructions
   hidden in a source file must not be able to change what the system does, only what it
   reads.
3. **Third-party kits and plugins** — they execute in our process. Validate manifests,
   reject bundled binaries, and be explicit in the docs that installing a plugin is a trust
   decision. Never claim a sandbox we do not have.
4. **Config and deployment input** — a provider `baseUrl` from config is an SSRF vector.
   Fetches driven by configuration or model output must not be able to reach internal
   network ranges by default.

### Concrete rules

- Secrets stay server-side or in the OS keychain — never in a client bundle, never in a
  document or export, never logged, never echoed back in a prompt.
- No student PII (R12). This keeps the GDPR / FERPA / COPPA / VN Decree 13 surface near
  zero — that property is worth protecting deliberately.
- **Media handling:** validate type and size, store outside the web root, serve with a
  restrictive `Content-Type` and `Content-Disposition`. **SVG uploads are sanitised** —
  SVG is executable, and this product deals in SVG all day.
- **Archive extraction** (content packs) guards against zip-slip and decompression bombs.
- Path construction from user or model input is normalised and confined; never concatenate.
- Local models are a security feature — a school can run fully offline. Never break that.

### Automated in CI, on every PR

- **CodeQL** (SAST) · **dependency audit** · **licence compatibility check** — a dependency
  that is not Apache-2.0-compatible fails the build rather than being noticed at release.
- **Secret scanning with push protection** is GitHub's native feature, enabled in repository
  settings rather than as a workflow step. Push protection rejects a secret before it
  reaches the repository, which is the only moment the problem is still cheap; scanning
  afterwards means the credential is already published and must be rotated.
- GitHub Actions **pinned by commit SHA**; Dependabot for updates.
- **CycloneDX SBOM** and **Sigstore signing** per release; npm provenance on publish.

### Penetration testing

Automated scanning is not a pentest, and saying so plainly matters more than the schedule.

- **Before the first release that accepts uploads or stores keys** (Phase 4–5), run a real
  assessment of the self-hosted app: authentication, file upload, SSRF through provider
  config, XSS through SVG and model output, path traversal in the media store, and key
  handling.
- Re-assess when the trust boundary changes — third-party plugin loading, any hosted
  multi-tenant instance, or a sharing feature.
- Findings are fixed at the owning layer with a regression test (R13), and the threat model
  above is updated. A pentest that produces a patch but no test invites the same bug back.

### Disclosure

Report vulnerabilities per `SECURITY.md` — never in a public issue first. Security fixes may
skip the usual release cadence; they never skip review.

## 10. Definition of Done

Before reporting any change complete:

- [ ] **Searched and reused** existing modules — no duplication (§0.2).
- [ ] **Impact assessed** on shared schemas, ports, registries and profiles (§0.3).
- [ ] `pnpm build` — passes. Run it first; the checks below depend on its output.
- [ ] `pnpm lint` — 0 errors.
- [ ] `pnpm typecheck` — passes in every package.
- [ ] `pnpm test` — passes; new logic has tests. Pure packages have deterministic golden
      tests.
- [ ] **Self-tested end-to-end** — real run, happy path + edge cases (§0.5).
- [ ] **Localhost guarantee intact** (R9) — still works with no key and no network.
- [ ] Nothing hardcoded that belongs in a registry, profile or config (R1); no new vendor
      name outside `packages/adapters` (R8).
- [ ] Purity holds (R7); no LLM in a gate (R2); `frame` still deterministic (R3).
- [ ] **Embeddability intact** (R16) — no new module-level singleton, no ambient env read, no
      bucket-specific URL written into a document.
- [ ] No natural-language string or locale-specific constant added to the engine (R4).
- [ ] Accessibility checked — both themes, keyboard, reduced motion.
- [ ] SPDX header on new files; changeset added if a public API changed.
- [ ] Commit signed off (`-s`), Conventional Commit message, **no AI attribution**.
- [ ] Architectural decision changed? → update `docs/ARCHITECTURE.md` **and** add an ADR.

## 11. Adding a feature — the short version

1. Read this file and `docs/ARCHITECTURE.md`. Decide the **layer** (§2).
2. Ask first: **is this a registry entry rather than code?** (§3, R1). Usually it is.
3. Pure logic → `core` / `quality` / `generator`; vendors → `adapters`; UI → `react` /
   `editor` / `apps`.
4. Ports for anything non-deterministic. Zod at every boundary.
5. Write code per §5. Never break §1.
6. Run §8 until green.
7. New architectural decision → update ARCHITECTURE.md + add an ADR.

**Common commands** (from the repo root): `pnpm dev` · `pnpm build` · `pnpm typecheck` ·
`pnpm lint` · `pnpm test` · `pnpm format` · `pnpm changeset`.
